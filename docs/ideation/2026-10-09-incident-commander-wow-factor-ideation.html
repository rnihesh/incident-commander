Grounding Context

Codebase Context

Incident Commander is a FastAPI + FalkorDB on-call agent with a Next.js console. The full flow runs: inject a fault, a reflex answer in about 2 ms, bitemporal as-of snapshots built with GRAPH.COPY, an elimination funnel, an absence certificate and necessity proof, a verdict, a rollback rehearsal on a cloned graph, a simulated PR, commit status and page, and a memory write-back. Judge mode adds blind commit-reveal injection and a tamper panel that flips proofs to FALSIFIED. Other pages cover replay, public proof pages, storm collapse (WCC plus betweenness) and a benchmark. An MCP server exposes the read-only tools. The live LLM benchmark puts the graph agent at 50/50 with both gpt-6-luna and local qwen3:8b. The same model with the full catalog in its prompt got 26/50, Opus 5.5 full context got 4/10, and vector RAG got 4/50.

Gaps that matter for wow:

  • The README has no images.
  • The first paint is an empty state.
  • The "Was it my deploy?" panel is mocked (Exonerate.tsx:14).
  • The learning curve never shows a contradiction (learning_curve.json: contradictions 0 in every row).
  • Several FalkorDB features go unused in product code: GRAPH.EXPLAIN/GRAPH.PROFILE, algo.pageRank, algo.SSpaths, and the GraphRAG-SDK.

External Context

The AI SRE market (Cleric, Resolve.ai, Traversal, Datadog Bits AI, incident.io) sells autonomy plus accuracy. Nobody shows re-runnable proofs, tamper detection or as-of time travel. The hackathon rules reportedly require FalkorDB to be "primary and central". The tracks are reportedly named Investigation & Risk (multi-hop link analysis, evidence and case mapping, explainable results), Best Agentic AI Use Case and Best Use Case of the GraphRAG SDK; that may differ from the README's track names, so verify. Useful analogies: chess-engine analysis lines, Hawk-Eye/VAR review, the courtroom chain of custody, and phylogenetic bootstrap.

1. Refutation engine: check any claimed root cause

IDEA 1Outward trust artifactsConfidence 80%Complexity Medium
Description
One read-only primitive runs the same EXPLAINS predicate the agent uses against any claimed entity id on the incident's as-of snapshot. It returns VERIFIED, or REFUTED with the first failing clause and the query, or "a rival qualifies". It surfaces three ways. (a) /benchmark gets a "Why it was wrong" column: every wrong answer from the gpt-6-luna and Opus full-context and vector runs is re-checked on its regenerated case world and refuted on a named clause. (b) An MCP verify_claim tool lets another agent (Claude Desktop, qwen) submit its answer and get graded. (c) A Hawk-Eye-style judge challenge replaces the mocked "Was it my deploy?" panel: tap an eliminated change and watch the live check stop on the clause that rules it out.
Axis
Outward trust artifacts & shareability (also judge play and agent coordination)
Basis
direct: predicate.py returns failed_clause in a fixed order (after_onset, origin, coverage, order, signature). The benchmark reports store per-case predicted, root_id and rng_seed; Opus case c000 predicted chg-05692 against root chg-05690. Exonerate.tsx:14 reads "Mocked against the completed incident's certificate", and line 63 uses fakeHash. mcp_server.py:14-16 binds a bearer token to a session world.
Rationale
It turns the headline number ("a frontier model got 4/10") from a claim into clickable evidence, removes the one visible fake in a product whose pitch is "no simulation", and makes the graph a trust layer other agents call. That fits both the Investigation & Risk "explainable results" brief and the agentic track. The new backend is one primitive.
Downsides
Case worlds must regenerate exactly from their seeds; verify one before trusting all. The Opus pool is only 6 wrong answers, so the 50-case gpt-6-luna run carries the column. A judge challenge must stay read-only and never mutate the main incident.

2. Query X-ray: FalkorDB's plan under every cut

3. Forgetting curve: memory that unlearns

IDEA 3Agent memory over timeConfidence 75%Complexity Medium
Description
Extend ic learn with a single scripted contradiction. After the learned coupling reaches high confidence, the world changes (a real Change removes the coupling) or a decoy incident has both ends symptomatic but no path through the learned edge. Confidence visibly halves, drops below the 0.25 recall threshold, and memory stops seeding that suspect. The learning-curve chart gains a confidence line that rises and then falls.
Axis
Agent memory & coordination over time
Basis
direct: learning_curve.json has contradictions = 0 in every row. memory/writeback.py sets CONTRADICT_FACTOR = 0.5, and tools/recall.py sets MIN_CONFIDENCE = 0.25. The README's Track 2 text claims confidence "halves when contradicted", and the saved run is one seed with a curve that only rises.
Rationale
A memory that only learns is a cache. Showing it unlearn when the world changes closes an honesty gap a sharp judge would spot, and it makes the memory story about reasoning, not storage.
Downsides
The decoy must satisfy the contradiction rule exactly, and the current injector cannot force the caller service, so it needs the scratch-probe trick already used in learning_curve.py. Keep the published curve until the new run is accepted. Skip the multi-agent and soak variants.

75%

4. Clause bars: the certificate as a VAR review

IDEA 4First 30 secondsConfidence 80%Complexity Low
Description
Render the absence certificate as one bar per candidate with five segments: after onset, origin, coverage, order, signature. The predicate checks clauses in a fixed order, so every segment before a candidate's failing clause is genuinely passed (green), the failing clause is red, and the rest are grey (not reached). Only the root fills all five. A "VAR" time strip draws the earliest symptom onset as the offside line and marks changes past it.
Axis
First-30-seconds demo moment
Basis
direct: predicate.py uses CASE WHEN event_time >= earliest THEN 'after_onset' WHEN NOT home_fails_first THEN 'origin' … END AS failed_clause, and the certificate already returns event_time, earliest and failed_clause. Today Certificate.tsx renders this as a table. external: FIFA VAR's calibrated offside line.
Rationale
"Elimination by proof" is the product's core idea and its hardest panel to explain. Bars read in under two seconds of video and need no backend change.
Downsides
The labels must not suggest clauses after the failing one were evaluated; grey means "not reached". Frontend only.
Confidence
80%

6. Fragility map: the agent tells you how to beat it

IDEA 6Judge playConfidence 55%Complexity Medium-High
Description
After a verdict, a capped background job (about 10 edits) tries single tamper edits on GRAPH.COPY clones and re-runs the predicate. The edits are removing each hop of the causal path, adding a deploy upstream of the nearest eliminated candidate, and shifting the root's timestamp. It reports which edits would flip the verdict ("falsified by any of these 2 edits"), and the tamper panel pre-fills them as "try these". When the judge applies one, the predicted flip comes true.
Axis
Judge interactivity & adversarial play
Basis
direct: TamperPanel.tsx offers add_deploy_upstream, remove_edge and change_timestamp. judge.ts flippedProofs() already names the responsible nodes. predicate.py computes shortestPath and unreached, so removing an edge either reroutes or fails coverage. MaxFlow was blocked earlier because it returns no cut, and single-edge enumeration sidesteps that.
Rationale
It inverts the adversarial setup: instead of surviving random tampering, the system predicts its own falsification and the judge confirms it. No AI SRE product shows proof brittleness.
Downsides
The highest effort and risk of the set. Runtime per clone on the 858-service world is unmeasured, it must stay off the critical path, and it touches the judge flow. Stretch goal.

55%
