Grounding Context

Topic Context

Subject. "Incident Commander" is a solo entry (one developer plus an AI coding agent) for the "Graph Hacks: Context for AI Agents" hackathon by WeMakeDevs x FalkorDB, Oct 15-18 2026 (four build days; no product code before Oct 15; 2,552 registrants). The primary target is Track 1, "Agents That Act on Connected Data" (multi-hop reasoning, graph queries and algorithms as agent tools, tool selection through MCP, actions based on graph, explainable results). It also enters Track 2, "Agent Memory & Coordination", and Track 3, "Company Brain". Side prize: best blog post.

Rules. FalkorDB must be the primary graph database and central: if the product works with FalkorDB removed, it does not qualify. Data must be public, synthetic, or the entrant's own. Submission needs a public repo, a README with the graph data model and the list of Cypher queries and algorithms, a demo video of about two minutes, and a live deploy or local setup. AI assistant use must be disclosed, and the entrant must be able to explain the graph model, queries, and architecture to judges.

Stack. Python (uv) with FastAPI backend, Next.js UI. LLMs: OpenAI primary, Gemini free tier or Ollama swappable.

Locked base concept

An alert webhook (or an "inject fault" button) starts a thin OpenAI tool-calling agent that picks graph tools from a shared tools layer, also exposed as an MCP server. It reconstructs a bitemporal service topology as of alert time (edges carry valid_from, valid_to, recorded_at), computes the upstream closure and the shortest causal path from the alert to a root-cause change (deploy, config, flag, commit), and emits a reproducible absence certificate (Cypher, params, and result hash, re-runnable in FalkorDB Browser). A hybrid precedent lookup (vector index, fuzzy full-text, causal-path-shape fingerprint) feeds a hypothesis ledger stored as graph nodes. The agent then opens a real GitHub rollback PR on a demo repo, pages the owner via webhook, and writes memory back (Incident, CAUSED_BY, REMEDIATED_BY with confidence reinforcement and decay) so a second similar alert resolves faster. A synthetic world generator (about 400 services across 3 regions, with deploys, commits, config, flags, owners, teams, on-call, incidents, postmortems, ADRs), a fault injector, and a benchmark (graph agent vs vector-RAG vs full topology in the prompt) back it up. Every tool returns {result, cypher, params, nodes_touched, ms} and the UI streams over SSE.

Should-have: a second remediation agent sharing state via the graph, multi-graph prod/staging, MCP usable in Claude Desktop. Stretch: algo.MaxFlow counterfactual. Cut: GraphRAG-SDK, CDLP.

FalkorDB capabilities in play

Redis-module graph database on GraphBLAS sparse matrices. OpenCypher with variable-length paths and shortestPath(). HNSW vector indexes on nodes and relationships, RediSearch full-text, a set of graph algorithms (BFS, SPpath, SSpath, Astar, MSF, PageRank, betweenness, harmonic centrality, WCC, CDLP, MaxFlow), and thousands of isolated named graphs per instance (GRAPH.COPY, GRAPH.LIST). No native datetime type (use epoch ints). Official MCP server. FalkorDB Browser for raw graph viewing.

Verified FalkorDB facts

  • GRAPH.COPY exists and snapshots indexes too; copy timing is undocumented, so benchmark it on day 1.
  • A relationship vector index and db.idx.vector.queryRelationships are confirmed.
  • algo.maxFlow returns only edges, edgeFlows, and maxFlow: no min-cut or residual graph.
  • algo.SSpaths / algo.SPpaths are weighted (verify config keys). algo.WCC is undirected. algo.betweenness is sampled, so pin samplingSeed.
  • There are no triggers or change notifications.
  • shortestPath disallows property filters in the pattern, so a bitemporal as-of query must use a materialized as-of graph (GRAPH.COPY plus deleting invalid edges) or a variable-length MATCH with WHERE all(...).
Prior-art warning

arXiv 2606.08590, "Auditable Graph-Guided RCA for Kubernetes Incidents", overlaps the word "auditable". Do not claim "first auditable graph RCA".

External context

  • Prior FalkorDB hackathon ("Memory Meets Motion", SF, Aug 2026, 13 projects): the winner, Atrium, modeled student misconceptions as graph nodes; a clear graph-native hook beat a feature list. Judges valued complex traversals, precedent reasoning, absence verification, and real-time event-to-action. Adjacent entry "Hopper" walked advisory, package, dependency, repo, service, customer. No SRE or incident project appeared there.
  • Commercial AI-SRE: Causely (causal graph, abductive inference, closed), Dynatrace Davis/Smartscape (deterministic topology traversal, closed), Datadog Bits AI SRE (hypothesis tree with rejected hypotheses shown, telemetry-based, closed), Resolve.ai (autonomous), Cleric (self-learning, read-only), Traversal (causal ML), HolmesGPT (CNCF OSS, agentic loop over toolsets and runbooks, no graph), Komodor Klaudia (K8s multi-agent).
  • Closest hackathon prior art: PagerDruid (Neo4j Aura Agent challenge winner: dependency graph, deterministic Cypher-template tools, shortest path, blast radius, owner routing; no embeddings, memory, or proofs). Sherlock (IBM hackathon: alert to git forensics to PR, no graph). RecallOps/CascadeFlow (vector-only incident memory). Academic: GALA, Praxis, KGroot.
  • Adversarial judge review of the base concept: graph centrality 8, FalkorDB breadth 6, originality 5 (to 6), demo wow 8, Track 1 fit 9, Track 2 fit 4, Track 3 fit 5, explainability 9; roughly 20-25% win probability. Attacks: "this is Causely with a smaller graph"; "synthetic world, synthetic win: you planted the path"; "the graph is a lookup table over canned Cypher templates; Postgres + recursive CTE + pgvector looks identical"; "60 services fits in a prompt".
  • Gaps nobody demonstrates: graph-structural negative proofs; visible replayable traversal with algorithm steps; native graph algorithms as MCP tools; a change-centric graph; memory write-back that changes later traversals; vector plus graph precedent in one store; open and self-hostable.

1.

Proof-Carrying Incident Response

  • Confidence: High
  • Complexity: Medium
Description
Every claim the agent makes is a pre-registered, machine-checkable Cypher proof. Each Hypothesis declares its falsifying query before running; results, a hash, and a prev_hash form an append-only chain in the graph. The UI shows an elimination funnel (312 changes, then 41, then 6, then 1), each cut a clickable query. A necessity check removes the suspect in an as-of snapshot and shows the alert loses all explanation (a uniqueness certificate). A "Was it my deploy?" exoneration receipt is the same machinery applied per deploy. A Verify button re-runs the whole chain (VERIFIED / DRIFTED / FALSIFIED), and a GitHub check on the rollback PR re-runs the proofs against FalkorDB.
Axis
Reasoning & proof
Basis
direct: the grounding records an absence certificate and hypothesis ledger in the base concept, that judges valued absence verification, and an adversarial review scoring explainability 9 but originality only 5. external: proof-carrying code, Certificate Transparency, and clinical pre-registration; Datadog Bits AI SRE shows rejected hypotheses but is closed and unverifiable.
Rationale
It turns "explainable" into "independently checkable", which is the identity of the product and the lever on the originality score. The same proof machinery yields the funnel, the uniqueness certificate, the exoneration receipt, and the PR check, so one mechanism carries several demo beats.
Downsides
arXiv 2606.08590 overlaps the word "auditable", so the claim must be framed carefully. Dominators are computed in Python, not FalkorDB.
Meeting test
"Every sentence the agent says has a button that re-proves it against the database."
2.

Judge Plays Chaos Monkey

  • Confidence: High
  • Complexity: Medium
Description
A judge clicks any node to break it. The injector publishes only a SHA-256 commitment; ground truth lives in a sealed answer_key graph the agent's tools cannot read. The agent finds the fault blind, then the reveal matches the commitment. Second beat: the judge inserts or deletes an edge in FalkorDB Browser and the stored certificate flips to FALSIFIED in under a second, naming the violating node; the agent then re-derives.
Axis
Demo & judge experience
Basis
direct: the adversarial attack "synthetic world, synthetic win: you planted the path"; FalkorDB multi-graph isolation; certificates that are re-runnable in FalkorDB Browser.
Rationale
The commitment hash and the unreadable answer graph remove the "you planted the path" objection by construction, and the judge's own edge edit shows the certificates are live rather than canned.
Downsides
The live fault must be reliably solvable, so pre-test the injector classes and record a fallback take.
Meeting test
"The judge picked the fault, and the agent found it blind."
3.

Time Machine: as-of snapshot graphs + kill-cam replay

  • Confidence: High
  • Complexity: Medium
Description
Edges are bitemporal (valid_from, valid_to, recorded_at). The agent materializes the world as of alert time into its own named graph (GRAPH.COPY plus pruning), so every algorithm runs on the true past topology. A scrubber replays the outage spreading hop by hop. A toggle between "as-happened" and "as-known-then" exposes late-arriving or backdated evidence ("recorded 14 min after alert - not available to on-call"). A silent-failure mode uses future-dated expiry edges (TLS cert, TTL, quota) so the agent can prove a cause even when nothing changed.
Axis
Credibility & FalkorDB depth
Basis
direct: the bitemporal base design, plus the verifier finding that shortestPath cannot filter on properties, so as-of snapshots are required. external: a search found no prior RCA system that distinguishes transaction time from valid time.
Rationale
The FalkorDB limitation turns multi-graph from a nice-to-have into a load-bearing feature, which answers "Postgres looks identical". The as-happened versus as-known-then toggle is a novel view of an incident that no competitor shows.
Downsides
GRAPH.COPY timing is unknown: benchmark it on day 1, with variable-length MATCH plus WHERE all(...) as the fallback.
Meeting test
"Drag the slider back before the deploy and watch the outage path vanish - and the graph knows when evidence was planted."
4.

Scar Tissue: memory that rewrites the topology

  • Confidence: Medium-High
  • Complexity: Medium
Description
After each resolved incident the agent writes LATENT_DEPENDS_ON edges (real but undeclared couplings, such as a shared cache) with reinforced or decayed confidence, plus suspicion weights on confirmed path edges. The next similar alert on a different service routes through the learned dashed edge in one hop, shown with a learning-curve chart (hops and time across seeded incidents). The investigation subgraph doubles as the handoff baton between triage and remediation agents (Track 2 shared state). Open postmortem recommendations that intersect the new causal path raise a banner such as "predicted by REC-0871-3, open 194 days" (Track 3).
Axis
Memory & learning over time
Basis
direct: the identified gap "memory write-back that changes later traversals"; Track 2 fit scored 4 and Track 3 fit scored 5 in the adversarial review. external: RecallOps and CascadeFlow keep incident memory as vectors only.
Rationale
Memory that changes the graph's shape, not just a lookup table, is a graph-native hook and the strongest lever on the weak Track 2 and Track 3 fit scores.
Downsides
A learning curve on self-generated data can look circular, so use held-out fault classes.
Meeting test
"Watch the graph grow a new edge after the incident - and the next alert use it."
5.

Storm Collapse: 300 alerts, 2 incidents, 3 changes

  • Confidence: Medium
  • Complexity: Medium
Description
Storm mode fires 200-400 alerts. algo.WCC splits independent incidents, algo.betweenness (seeded) finds chokepoints, and a greedy set-cover over upstream closures finds the minimal explaining set ("incident B needs flag + config together - neither alone covers all 6"). A counter shows pages collapsing from 312 to 2.
Axis
Reasoning & proof
Basis
direct: WCC and betweenness are named as agent tools, and real-time event-to-action was valued by judges. external: Groot assumes a single root cause; PagerDruid handles a single alert.
Rationale
It uses native graph algorithms for multi-root-cause incidents, a case the closest prior art does not handle, and the page-count collapse is an instantly legible number.
Downsides
It adds a second scenario to the demo, so keep it to one storm beat.
Meeting test
"Seventeen alerts, two incidents, three changes - and proof two of them were needed together."
6.

Multiverse Rollback Rehearsal

  • Confidence: Medium
  • Complexity: Medium
Description
Before opening the real PR, the agent runs GRAPH.COPY on the as-of world, applies the rollback as mutations, and re-checks alert reachability. It ranks candidate remediations across N universes and refuses a rollback that does not clear the fault. A side-by-side diff shows prod versus sandbox.
Axis
Actions & the real-time loop
Basis
direct: GRAPH.COPY and multi-graph support are verified; safe action is a stated concern. reasoned: there is no clean Postgres equivalent of cheap whole-graph clones with graph algorithms running on them.
Rationale
It makes acting on the graph safe, which strengthens the Track 1 "actions based on graph" criterion and reuses the snapshot machinery from idea 3.
Downsides
It depends on copy timing. The MaxFlow "what saturates next" counterfactual is deferred because there is no min-cut.
Meeting test
"It rehearsed the rollback on a copy of the world before touching the real one."
7.

Postgres Twin + Reflex-vs-Proof latency

  • Confidence: High
  • Complexity: Medium
Description
The same synthetic world, scaled to about 5-10k services, is loaded into Postgres (recursive CTE plus pgvector). Every tool has an engine switch. A benchmark page shows latency per step and the accuracy of the graph agent versus vector-RAG versus full topology in the prompt (token overflow shown). The first SSE frame is a sub-100ms "reflex" (precomputed blast radius and top suspects) delivered before the slow proof.
Axis
Credibility & FalkorDB depth
Basis
direct: the adversarial attacks "Postgres + CTE + pgvector looks identical" and "60 services fits in a prompt", plus the GraphBLAS latency profile.
Rationale
It answers the two sharpest judge objections with measurements rather than argument, and the reflex frame makes the latency advantage visible in the first moment of the demo.
Downsides
The Postgres twin is extra work; it can be trimmed to closure and shortest-path queries only.
Meeting test
"We built the Postgres version so you don't have to ask."
